# Using the dashboard's numbers in Tableau

The model stays in Python. Tableau reads its results from tidy CSV files, so analysts can slice, filter and build their own views on exactly the numbers the web dashboard shows. Works the same in Tableau Desktop, Cloud, Server and Public.

## 1. Get the files
They are in `exports/tableau/` in this repository (download the repo as a ZIP, or clone it). To regenerate them after a rebuild:

```bash
python scripts/export_tableau.py
```

`product_monthly.csv` (about 22 MB) is not stored in the repository; the command above creates it. `python scripts/validate_data.py` then proves the export gives the same suggested actions and probabilities as the dashboard.

## 2. Connect in Tableau Desktop
1. **Connect → Text file**, choose one CSV, for example `segments.csv`.
2. Drag more tables onto the canvas and relate them on the key:
   - segment tables (`segments`, `segment_monthly`, `forecast_monthly`, `monitoring`) join on **`segment_id`**
   - product tables (`products`, `product_monthly`, `product_topics`) join on **`product_id`**
3. Tableau reads dates (`yyyy-mm-dd`) automatically. Set `month`, `quarter_start` and `date` as Continuous dates for trend lines.
4. Tables like `cohorts`, `age_mix`, `topics_category`, `amazon_*` and `market_series` stand alone; connect them as their own data sources.

Tip: use **Relationships** (the default in current Tableau) rather than joins, so each table keeps its own level of detail and you avoid duplicated rows.

## 3. Tableau Cloud, Server or Public
- **Cloud / Server:** publish the workbook with an extract. To refresh, replace the CSVs and refresh the extract (Tableau Bridge or a scheduled refresh if the files sit on a shared location).
- **Public:** everything you publish is visible to anyone. See the licence note below before choosing this.

## 4. Five good starter views
1. **Scorecard.** `segments`: rows = `segment`, columns = `expected_change`, `chance_of_growth`, `confidence`; colour by `suggested_action`. Filter by `segment_type`.
2. **Forecast with its range.** `forecast_monthly` for one segment and measure: line for `expected`, shaded band between `low_80` and `high_80`. Add actual history from `segment_monthly`.
3. **On track?** `monitoring`: line for `actual`, band for `expected` range, highlight months where `position` is not Within.
4. **Product lifecycle.** `products`: x = `reviews_last_12m`, y = `rating_change`, colour = `lifecycle_stage`, size = `reviews`, filter by `product_type`.
5. **Topic heat map.** `topics_category`: rows = `topic`, columns = `period`, colour = `share_of_unhappy_reviews`. Or `product_topics` for one product.
Plus **Amazon revenue mix**: `amazon_revenue_mix`, stacked bars by `quarter_start`, coloured by `group`.

## 5. Keep these in mind (they are what make the numbers honest)
- **The category data ends March 2023.** Forecast months start April 2023 and are the model's view from that date, not from today. Amazon's own results (`amazon_*`) and the market series run to 2026.
- **`sales_proxy` is not revenue.** It is the price of each verified-purchase review, with missing prices estimated (`price_is_estimated` in `products`; `sales_listed_prices_only` shows the lower bound).
- **Use the model's forecast, not Tableau's.** Tableau's built-in Forecast is a different method and would give different numbers from the dashboard.
- **Check `confidence` and `tentative`** before acting on a segment; low-confidence segments are watch-lists, not budget lines.
- **Suggested actions use default thresholds** (invest at 70% chance of growth, risk at 30% or less, rating floor 4.0). Rebuild the logic in Tableau calculated fields if you want different thresholds.

### `segments.csv`  (72 rows)
One row per brand, product type, price band, product or parts-vs-appliances group: the scorecard behind the Executive brief.

| Column | Meaning |
|---|---|
| `segment_id` | Stable key, for example brand:GE. Join other segment tables on this. |
| `segment_type` | Brand, Product type, Price band, Product, Parts vs appliances, or Whole category. |
| `segment` | Display name. |
| `measure` | What the money columns measure: Sales proxy ($), or Reviews when a segment has no price data. |
| `last_12m` | Total over the last 12 months of data (to Mar 2023). |
| `prior_12m` | Total over the 12 months before that. |
| `change_vs_prior_12m` | last_12m divided by prior_12m, minus 1. |
| `expected_next_12m` | Model's expected total over the 12 months after Mar 2023. |
| `low_case_next_12m` | 10th percentile of the same total (likely range, low end). |
| `high_case_next_12m` | 90th percentile (likely range, high end). |
| `expected_change` | expected_next_12m divided by last_12m, minus 1. |
| `chance_of_growth` | Probability the next 12 months beat the last 12, from 1,000 simulated futures. |
| `rating_last_12m` | Average star rating, weighted by reviews. |
| `rating_prior_12m` | The same for the 12 months before. |
| `rating_change` | rating_last_12m minus rating_prior_12m. |
| `forecast_model` | Model chosen by backtest. |
| `typical_forecast_miss` | Weighted average monthly forecast error in backtests (0.18 = 18%). |
| `forecast_bias` | Average over-forecast in backtests; positive means forecasts ran high. |
| `range_coverage_80` | Share of backtest outcomes inside the 80% range (the aim is 0.80). |
| `confidence` | High (miss up to 15%), Medium (up to 30%), Low (above 30%). |
| `suggested_action` | Invest, Fix quality, Risk or Watch, using the dashboard's rules at default thresholds. |
| `action_reason` | Plain-language reason for the action. |
| `tentative` | True when confidence is Low. |
